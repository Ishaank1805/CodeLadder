# CodeLadder: project plan

**Goal.** A harness that writes code with a ladder of free open-weight models, decides at each step to accept, repair, resample, escalate or abstain, and is calibrated so that the rate of accepted-but-wrong code stays at or below a chosen α (with confidence 1 - δ) at minimum cost. We report reliability, cost, coverage, energy and robustness under shift.

Work is ordered by dependency. Status: [x] done, [~] in progress, [ ] to do. Results so far are in [RESULTS.md](RESULTS.md); the operational state (running jobs, how to resume) is in [STATUS.md](STATUS.md).

## 2. Harness and methods

- [x] LiveCodeBench adapter (stdin and LeetCode method modes, LiveCodeBench graders, lazy loading).
- [x] Confidence scores: agreement, log-probability, verbalised self-confidence, agreement x self-confidence (best so far), visible-only (`evaluate --score`).
- [x] Threshold families: shared threshold (fixed-sequence testing), two-level (escalation + final-tier thresholds) with Bonferroni-path calibration (default) or Pareto Testing, sub-ladders (any subset of tiers) and single-model selection (`evaluate --family shared|two_level|subsets|singles`).
- [x] Selection among certified settings prices abstention (`--abstain-factor κ`); plain cost (κ = 0) is degenerate once cheap sub-ladders exist.
- [x] Group-conditional (Mondrian) calibration per benchmark, reported alongside pooled calibration.
- [x] Baselines: each model alone (uncalibrated), calibrated single model, hand-picked-threshold ladder, label-using oracle.
- [x] Published baselines, implemented faithfully and replayed on the same tasks and costs, over 100 random splits of their own (`baselines.py`): Model Cascading for Code (k solutions and k self-generated tests of up to 4 assert lines per model, score n_s x n_t, escalate below theta x k x N_t, theta tuned on the calibration half) and Bayesian self-escalation (greedy generation with per-token logprob / entropy / top-2 margin, logistic belief on their running means, abort and escalate below tau, tuned likewise). Generation: `make-selftests`, `make-traces` (all four Qwen tiers); execution: `baseline-exec`; replay: `codeladder baselines`. Neither abstains, so their risk is the error rate; tuning on calibration data gives no guarantee, which the violation rate shows.
- [x] Fixed actions (always repair, always resample) against a learned repair-or-resample policy, on the same splits (X4, `codeladder actions`).
- [x] Learned up-front router as a baseline (X9, `codeladder route`).
- [x] Figures: per-run guarantee and cost-risk (`plot_results.py`), frontier across κ (`plot_frontier.py`), and report figures from all results (`report_figures.py`, 13 figures: validity over every run, published baselines, temporal shift, repair, energy, stdin signals, conditional risk, router, economics, guaranteed baselines, bootstrap intervals, oracle sensitivity, P(True)) and report tables (`report_tables.py`); BigCodeBench panels and rows appear when its results exist. To do: API LiveCodeBench panels when those pools are complete.

## 4. What the results so far change

- **Calibration sample size is the main limit at α = 0.10 and below.** With 271 calibration tasks only settings with true risk around 7% or less can be certified. LiveCodeBench (1,054 tasks) is therefore central, not optional.
- **MBPP+ has a floor of confidently wrong answers** (~14% silent failures at every model size). Report HumanEval+ and MBPP+ separately as well as pooled.
- **Agreement weakens as models grow; combining it with self-confidence helps.** Default score for headline results: `agreement_selfconf` (requires annotation, which every tier now gets).
- **Stdin probes help only a little** (AUROC 0.661 to 0.677 against 0.670 to 0.756 for argument probes on LeetCode-style problems): 56% of stdin silent failures are too-slow programs that small probes cannot expose. Simple size-scaling (count line + array/string/records with N up to the stated limit) only fits 91 of 610 stdin problems and 21 of the 90 with 1.5B silent failures, so it is not worth it. Done instead as X2: a fixed model writes a stress-input generator per problem from its statement and constraints (one call per problem, counted as harness cost), which lifts AUROC by 0.08 to 0.14 on every tier.
- **Headline (20 Oct): under a finite-sample risk guarantee, ladders pay off only for cost at loose α on the easier benchmark** (about half the cost at α = 0.20 on HumanEval+/MBPP+); on LiveCodeBench and at strict α calibrated selection of one model is as good or better, even with lean lower rungs (lower-tier budget 1: about 35% cheaper ladders, still not better than 32B alone). Published cascades without abstention cannot operate below the models' error floor and overshoot α when tuned. Refined 25 Oct (X13): the saving is bounded by the share of tasks the cheap rung certifies at α (the cheap-share law), so it depends on the models and the benchmark, not on prices.
- **The ladder must be allowed to skip tiers.** Ladders that always use every tier lose to a single calibrated model; with sub-ladders and a price on abstaining they match model selection at α = 0.10 and halve cost at α = 0.20. Searching more configurations costs power at α = 0.05 (price of flexibility), which more calibration data should shrink.
- **32B adds little on HumanEval+/MBPP+** (no better than 14B on HumanEval+, 2 to 3 times the energy); LiveCodeBench is where the top tier should matter.
- **Per-benchmark calibration needs more data per group;** keep pooled calibration as the headline and report Mondrian as an ablation.
